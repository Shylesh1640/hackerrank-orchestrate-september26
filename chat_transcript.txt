================================================================================
USER REQUEST
================================================================================
Build a production-quality Python solution that generates output.csv for every row in dataset/requests.csv. The system must determine whether a user can safely afford the requested expense by reconstructing their financial state, forecasting cash flow for 90 days, evaluating all eligible payment plans, considering permitted flexible-spending changes, and deterministically verifying the final recommendation.

Core design principle: Do NOT use a machine-learning classifier as the final affordability decision-maker. The final decision must come from a deterministic financial simulation + constraint-checking + plan-ranking engine.

Use AI only where unstructured evidence genuinely requires interpretation:
1. financial messages
2. linked financial images

The AI component must extract structured financial facts. It must never override the financial rules or directly determine the final affordability decision.

DEVELOPMENT ITERATIONS
================================================================================

--- Iteration 1: Core Data Loading & Configuration ---
Created config.py with constants, file paths, and enums.
Created data/loader.py for CSV loading with proper date parsing.
Created finance/currency.py for deterministic exchange rate conversion using provided exchange_rates.csv.

--- Iteration 2: Financial Event Normalization ---
Created finance/events.py with NormalizedEvent dataclass and normalization logic.
Implemented direction sign normalization (income=positive, expense=negative).
Created finance/resolver.py for event lifecycle resolution:
- Handle linked_event_id chains (cancellations, amendments)
- Deduplicate events
- Filter invalid (failed, cancelled, unrealized gains)
- Detect recurrence from historical patterns (monthly/weekly/quarterly)

--- Iteration 3: Recurrence Detection Fixes ---
Initial issue: financial_events.csv lacks 'recurring' and 'frequency' columns.
Fixed by inferring recurrence from event patterns (3+ occurrences, consistent intervals).
Added logic to distinguish fixed recurring (rent, salary) from variable (groceries, transport).
Protected categories: rent, housing, utilities, education, debt_repayment.
Variable essentials: groceries, transport (budgeted monthly, not recurring per-event).

--- Iteration 4: User Financial State Reconstruction ---
Created finance/state.py to build UserFinancialState at request_date:
- Current balance from profile
- Historical settled events applied to balance
- Future events categorized: confirmed_income, recurring_income, essential_expenses, flexible_expenses, confirmed_payments, pending_debits
- Applied user preferences: protected/reducible/stoppable categories, payment methods, max_installment_months

--- Iteration 5: 90-Day Forecast Engine ---
Created finance/forecast.py with run_forecast() producing daily balance projections.
Key insight: Variable essentials (groceries, transport) need monthly budget estimation, not per-event recurrence.
Implemented compute_variable_essential_budget() using mean of last 12 settled events * (30/7) for monthly.
Binary search for amount_safe_to_pay (0 to requested_amount, 20 iterations).
Earliest full payment search from request_date to min(desired_completion, request_date+90).

--- Iteration 6: Payment Plan Generation ---
Created planning modules:
- full_payment.py: amount_safe_to_pay + earliest_date calculation
- partial_payment.py: 2-payment split (amount_safe on request_date, remainder on earliest_full)
- installments.py: Parse request_payment_options.csv, filter by user eligibility (max_installment_months, desired_completion)
- spending_changes.py: Generate stop/reduce candidates from flexible expenses matching user preferences

--- Iteration 7: Plan Ranking & Verification ---
Created planning/ranking.py with deterministic sorting:
1. Complete by desired_completion_date
2. No spending changes
3. Minimize total cost
4. Earlier start date
5. Fewer payments
6. Lowest payment_option_id tiebreaker

Created verification/safety.py for authoritative plan validation:
- Payment chronology, totals, method eligibility
- Installment total matches supplied option total_payable_amount
- Spending changes valid (reducible/stoppable categories, min amounts)
- Full 90-day safety re-verification

--- Iteration 8: Message & Image Evidence Processing ---
Created evidence/messages.py with regex-based extraction for:
- Salary changes (English/Indonesian patterns: "gaji bulanan naik menjadi IDR...")
- Bonus confirmations
- Transaction cancellations/settlements/delays/amount changes
Employer messages treated as confirmed if definitive language ("naik menjadi", "berubah")

Created evidence/images.py with Tesseract OCR fallback (not available in environment).

--- Iteration 9: Integration & Pipeline ---
Created pipeline.py orchestrating:
1. Load all data
2. Extract message/image facts
3. Build user state with facts applied
4. Calculate amount_safe_to_pay, earliest_full
5. Generate candidate plans (full, partial, installments, wait)
6. Verify each plan, try spending changes if failed
7. Rank verified plans, select best
8. Generate explanation
9. Write output.csv

--- Iteration 10: Bug Fixes & Validation ---
Fixed date parsing (datetime vs date comparison errors).
Fixed recurrence generation to emit ONE series per category (not per historical event).
Fixed installment verification to compare against total_payable_amount not requested_amount.
Fixed message parsing for Indonesian salary notifications.
Fixed income classification to include "confirmed" status from messages.
Fixed NaN handling in output (empty strings for earliest_date when not affordable).

================================================================================
KEY TECHNICAL DECISIONS
================================================================================
1. Deterministic simulation over ML: All affordability decisions from 90-day forecast
2. Event lifecycle resolution: Explicit cancellation > newer record > settled > conservative
3. Variable essentials budgeting: Monthly mean from history, not per-event recurrence
4. Message parsing: Regex for multilingual (EN/ID) financial communications
5. Installment fidelity: Must exactly match supplied payment_option schedule
6. Spending changes: Only reducible/stoppable categories, max 3, no duplicate events
7. Conservative interpretation: When ambiguous, prefer financially safer outcome
